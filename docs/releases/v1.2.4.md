## Reuse saved AI credentials

- Fix repeated Keychain prompts when right-clicking files for AI analysis. Saved or unlocked keys are reused for the app session across file analysis, follow-up questions, retries, new conversations, and connection tests.
- Opening settings or changing the model no longer reads or rewrites the saved key. Leave the key field blank to keep it; replacement and removal are explicit actions. Credentials remain separate for each protocol and service address.
- Denied Keychain access stays inline in the conversation. Only **Unlock & Retry** or an explicit connection test retries authorization; repeated analysis no longer reopens settings or triggers another prompt.

Keys remain in macOS Keychain, with a temporary in-memory copy while the app runs. Because this release is ad-hoc signed, macOS may request authorization on the first use after updating.

Includes eight credential regression checks using synthetic keys and responses, alongside the existing core, HTTP, and AppKit checks.
